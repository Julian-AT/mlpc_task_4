## Threat Model

| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-01-03 | Feature arrays are concatenated in nondeterministic or inconsistent order, invalidating later model comparisons. | high | Sort selected feature keys, return/save `feature_keys`, and assert consistent segment count and final dimension. |
| T-01-04 | Non-feature arrays such as annotations, class names, or times are accidentally included as model features. | medium | Exclude metadata/control keys explicitly and require numeric arrays with the segment dimension first. |
</threat_model>

<feature>
  <name>Deterministic feature loading and concatenation</name>
  <files>src/data.py, tests/test_data.py</files>
  <behavior>
    Given an `.npz`-like mapping with numeric arrays whose first dimension is `T`, `concat_features` returns a two-dimensional matrix with rows `T`, concatenates feature keys in sorted order, flattens trailing dimensions, and returns the ordered feature key list.
    Cases:
    - `{"b": [[2], [3]], "a": [[1], [1]], "annotations": ...}` -> feature keys `["a", "b"]`.
    - Feature arrays with inconsistent first dimension -> raises `ValueError`.
    - No compatible feature arrays -> raises `ValueError`.
  </behavior>
  <implementation>
    Add `NON_FEATURE_KEYS`, `load_metadata`, `load_annotations`, `iter_feature_files`, `concat_features`, and a helper that normalizes selected arrays to `[T, D_i]`. Use `src.config` path constants by default but accept explicit paths for tests.
  </implementation>
</feature>
